UFS-Coastal files
=================

For DATM-coupled (``nws=4``) configurations, for example SECOFS and
STOFS-3D-ATL DATM+SCHISM and SECOFS DATM+SCHISM+WW3, prep also renders the
per-cycle UFS-Coastal inputs. It fills them in from the templates and fix files
that must already be staged in ``$FIXofs``.
:class:`~nos_utils.orchestrator.PrepOrchestrator` runs these as its UFS-only
steps: DATM blending and the ESMF mesh, then the configuration files.

.. list-table::
   :header-rows: 1
   :widths: 28 22 50

   * - File
     - Module
     - What it holds
   * - ``datm_forcing.nc``
     - :mod:`~nos_utils.forcing.blender`
     - GFS, or HRRR blended over GFS, on a regular lat/lon grid for CDEPS DATM.
       ``nx_global``/``ny_global`` in ``datm_in`` are taken from its dimensions.
   * - ``datm_esmf_mesh.nc``
     - :mod:`~nos_utils.forcing.esmf_mesh`
     - ESMF unstructured mesh of the DATM grid (all elements active).
   * - ``model_configure``, ``datm_in``, ``datm.streams``
     - :mod:`~nos_utils.forcing.ufs_config`
     - Filled from the ``*.template`` files in ``$FIXofs``: start time and
       length of the phase being prepped (nowcast, forecast, or both),
       ``dt_atmos`` (``ufs_coastal.dt_atmos``), DATM grid size and file names.
   * - ``ufs.configure``
     - :mod:`~nos_utils.forcing.ufs_config`
     - Copied from ``$FIXofs`` with the PET bounds set from the resource
       layout (MED, ATM, OCN, and WAV when wave tasks are configured) and the
       ``runSeq`` coupling interval set to the SCHISM time step, or to
       ``ufs_coastal.coupling_interval`` when that is an integer multiple of
       it. The WW3 component stanza comes from the system's own
       ``ufs.configure`` fix file.
   * - ``fd_ufs.yaml``, ``noahmptable.tbl``
     - :mod:`~nos_utils.forcing.ufs_config`
     - Copied from ``$FIXofs`` as they are.
   * - ``nest.ww3``
     - :mod:`~nos_utils.forcing.wave_boundary`
     - WW3 boundary spectra built from the GFS-Wave point spectra with
       ``ww3_bound`` (needs ``mod_def.ww3``). Runs when waves are enabled
       (``forcing.waves``) and ``$COMINgfswave`` is set.

``model_configure`` uses the same start time as
:mod:`~nos_utils.forcing.param_nml` and :mod:`~nos_utils.forcing.tidal`
(cycle minus nowcast length), which keeps the CMEPS clock in step with SCHISM.

The WW3 runtime files (``ww3_shel.nml``, ``mod_def.ww3``, ``ww3_grid.nml``)
come from ``$FIXofs`` and are not generated by nos-utils.
